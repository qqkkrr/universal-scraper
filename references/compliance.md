# 合规预检（Compliance Preflight）

> 这不是法律意见，是工程检查清单。最终合规判断由用户/法务确认。

## 为什么需要

“技术能抓”不等于“允许抓”。个人信息、平台 ToS、技术保护措施是三条独立红线；
反爬策略只解决第一条，不能替另外两条做决定。

## 三层判断

### 1. 硬红线（停止）

- 逆向/伪造签名、设备指纹、滑块/验证码绕过；
- 绕过登录、盗用/买卖 Cookie；
- 抓取私信、订单、支付、后台等非公开数据；
- 未授权采集敏感个人信息（手机/证件/实名/精确地址/支付）；
- 批量用户画像、转卖个人信息。

### 2. 条件允许（需授权 + 最小必要）

- 用户本人登录态，只读公开页面；
- 公开数据、低频、遵守 robots、可审计；
- 有合法性基础（同意/合同必要/法定义务/公共利益等）；
- 只取交付必需字段；脱敏/聚合；写明保存期限；到期删除；
- 规模较大时做个人信息保护影响评估（PIPIA）。

### 3. 正常能力

- 公开页面、官方 API、sitemap；
- 代理池用于可靠性/地域测试/负载分散，来源合法；
- 限速、退避、缓存、快照、离线解析；
- 数据质量校验、抽样复核、交付审计。

## 命令

~~~bash
# 配置
python3 -m universal_scraper.cli compliance \
  --config task.json --purpose "竞品公开价格监测" --scale 200 \
  --legal-basis "合同必要" --authorized --retention-days 30

# 任务包
python3 -m universal_scraper.cli compliance --task tasks/foo --json
~~~

退出码：green=0；amber=0（加 --strict 则 1）；red=2。

## 输出怎么用

- red：不要执行；先移除绕过手段，或改成公开/授权数据路径；
- amber：把 actions 里的“最小必要/脱敏/留存/合法性基础”写进任务说明；
- green：正常执行，仍保持限速与 robots。

## 个人信息最小化建议

- 用户 ID 做不可逆哈希后再入交付表；
- 不保留“昵称 + ID + IP”可直接定位的组合；
- 头像、信用、精确 IP 属非必需字段时直接删；
- 留言/评论只保留业务必需片段，设置保存期限；
- 交付层提供“字段删除/聚合”版本，原始数据限权访问。

## 与反爬红线的关系

反爬 skill 的红线解决“不要绕过技术保护措施”；本预检解决“是否有权处理这些数据”。
两者都过，才开工。
